1Image Acquisition & the Digital Image Model

Core idea

A digital image is a discretized sample of a continuous physical signal. Two independent discretizations happen:

  • Spatial sampling: continuous coordinates (x, y) → integer grid indices (pixel/voxel locations), governed by the sensor's sampling rate (e.g., CCD/CMOS array pitch).
  • Amplitude quantization: continuous intensity → a finite set of discrete levels (e.g., 8-bit → 256 levels per channel).

An image is formally a function f: D → R where the domain D (grid coordinates) and range R (intensity/color values) can each be discrete or continuous, scalar or vector. A grayscale photo is a 2→1 mapping; an RGB video is a 3→3 mapping (2 spatial + 1 time dimension, 3 color channels).

Landscape analogy: Imagine photographing a rocky coastline at sunset with a CCD camera. The continuous variation of light intensity across the cliff face gets carved into a grid of pixels (spatial sampling), and each pixel's brightness is rounded to one of 256 possible gray levels (quantization) — you lose the "infinite resolution" of the analog scene the moment the sensor's array captures it.

Representing an image in C++

struct Image {
    int rows, cols, channels;
    std::vector<unsigned char> data;  // row-major, size = rows*cols*channels
    unsigned char& at(int r, int c, int ch = 0) {
        return data[(r * cols + c) * channels + ch];
    }
};

Classify the domain→range mapping type for: (a) a stock index over time, (b) a color photo of a cliffside.

MEDIUM

Why is amplitude quantization a lossy, irreversible step even if spatial sampling were perfect (infinite resolution)?

Reveal answer
Quantization maps a continuous range of real-valued intensities to a finite set of discrete levels — many distinct analog intensities collapse onto the same output level (many-to-one mapping), so the original continuous value cannot be recovered exactly. This is analogous to lossy compression: information is destroyed, not just re-encoded.
MEDIUM

You capture a panoramic photo of a coastline in RGB at 8 bits/channel, resolution 4000×1200. Compute the storage in MB, and explain why storing it as three separate 2D arrays vs. one interleaved 3D array changes only memory layout, not information content.

Reveal answer
4000 × 1200 × 3 = 14,400,000 bytes ≈ 13.7 MB. Planar (three 2D arrays, R-plane then G-plane then B-plane) vs. interleaved (RGBRGBRGB... per pixel) store the same (row, col, channel) → intensity function; only the memory access pattern/cache locality differs, e.g., interleaved is often faster for per-pixel operations, planar is faster for per-channel operations like separate histogram equalization.
HARD

Given a CCD sensor with pixel pitch (center-to-center spacing) of 5 μm and an optical system that projects the scene at a given magnification, argue — without invoking the Fourier module yet — why spatial sampling can introduce visual artifacts (moiré/aliasing) when photographing a repetitive stone-brick wall pattern at a coastline fort.

Reveal answer
If the brick pattern's repetition period, once projected onto the sensor plane, is comparable to or finer than the sensor's sampling pitch, the discrete grid cannot faithfully represent the pattern's spatial frequency. High-frequency detail gets "folded" into lower, spurious frequencies in the sampled image — this is aliasing, and for regular patterns it manifests as moiré fringes. (Formal treatment: this is exactly what the Nyquist sampling criterion in the Fourier Analysis section explains.)

2Basic Operations: Resizing & Interpolation

Core idea

Resizing changes the sampling grid. Downsampling reduces the number of samples (risking aliasing unless pre-filtered); upsampling increases the number of samples, requiring us to invent intensity values at new grid positions that didn't exist before — this is interpolation.

Common interpolation kernels

MethodMechanicsComplexity / Quality tradeoff
Nearest-neighborCopy value of closest source pixelO(1) per pixel, blocky artifacts
BilinearWeighted average of 4 nearest neighbors, linear in each axisSmooth but blurs edges slightly
BicubicWeighted sum of 16 neighbors using cubic polynomial weightsSharper, more expensive, can overshoot (ringing)

Bilinear interpolation — the algorithmic core

For a target coordinate (x, y) mapped back into source space, let x0=floor(x), y0=floor(y), and fractional parts a = x-x0, b = y-y0. Then:

f(x,y) ≈ (1-a)(1-b)·f(x0,y0) + a(1-b)·f(x0+1,y0) + (1-a)b·f(x0,y0+1) + ab·f(x0+1,y0+1)
float bilinear(const Image& src, float x, float y) {
    int x0 = (int)std::floor(x), y0 = (int)std::floor(y);
    int x1 = std::min(x0 + 1, src.cols - 1);
    int y1 = std::min(y0 + 1, src.rows - 1);
    float a = x - x0, b = y - y0;
    float top    = (1-a) * src.at(y0,x0) + a * src.at(y0,x1);
    float bottom = (1-a) * src.at(y1,x0) + a * src.at(y1,x1);
    return (1-b) * top + b * bottom;
}
Landscape analogy: Imagine zooming into a photograph of a mountain ridge until individual pixels are visible as jagged blocks — that's nearest-neighbor. Bilinear interpolation instead "blends the fog" between adjacent sample points, producing a smoother (but softer) ridge outline, as if you gently diffused the boundary between rock and sky.

Why does nearest-neighbor interpolation produce "blocky" enlarged images?

Reveal answer
It simply replicates the nearest source pixel's value for every new target pixel without blending — so a single original pixel expands into a solid block of identical intensity, creating visible square artifacts at edges.
EASY

Trace bilinear interpolation: source pixels at (0,0)=10, (1,0)=20, (0,1)=30, (1,1)=40 (format (col,row)). Find the interpolated value at (0.5, 0.5).

Reveal answer

MEDIUM

You downsample a 1200×800 photo of a rocky coastline to 300×200 by simply picking every 4th pixel (no pre-filtering). What artifact should you expect, and what is the standard fix?

Reveal answer
Aliasing — fine texture in the rocks (high spatial frequency) will fold into false, lower-frequency patterns (moiré). Fix: apply a low-pass (blurring/anti-aliasing) filter before subsampling to remove frequency content above the new Nyquist limit.
MEDIUM

Why is bicubic interpolation described as capable of "ringing" (overshoot) near sharp edges, e.g., the silhouette of a lighthouse against the sky, while bilinear never overshoots?

Reveal answer
Bicubic weights include negative lobes (the cubic kernel dips below zero away from the center) to sharpen edges, which can push interpolated values beyond the local min/max of the neighborhood — producing halo/ringing artifacts. Bilinear weights are all non-negative and sum to 1, so its output is always a convex combination (weighted average) of the 4 neighbors, bounded within their min and max.
HARD

Design (in pseudocode) an image resize function that correctly composes anti-aliasing + resampling for arbitrary downscale factor s < 1, and explain the time complexity relative to naive per-pixel bilinear resizing.

Reveal answer
Pseudocode: 
Image resize_downscale(Image src, float s) {
    // 1. Low-pass filter with kernel sized to new Nyquist limit (~ sigma ∝ 1/s)
    Image blurred = gaussianBlur(src, sigma = 0.5 / s);
    // 2. Resample on the coarser grid using bilinear/bicubic on the blurred image
    int newRows = round(src.rows * s), newCols = round(src.cols * s);
    Image out(newRows, newCols);
    for (r, c in out)
        out(r,c) = bilinear(blurred, c/s, r/s);
    return out;
}
Complexity: Gaussian blur with a separable kernel of width k costs O(rows·cols·k) (two 1D passes instead of one 2D pass, since a 2D Gaussian factors into a product of 1D Gaussians). Resampling itself is O(newRows·newCols). Total ≈ O(N·k) for an N-pixel image, vs. naive resize without blur which is O(newN) but produces aliasing — the "correctness" cost is the added O(N·k) blur pass.

3Point Operations & Histogram-Based Processing

Core idea

A point operation transforms each pixel's intensity independently of its neighbors: g(x,y) = T(f(x,y)). The histogram h(k) = count of pixels with intensity k summarizes the global intensity distribution and drives operations like contrast stretching and equalization.

Histogram equalization — the algorithm

  1. Compute histogram h(k) for k = 0..L-1.
  2. Compute normalized cumulative distribution function (CDF): cdf(k) = Σ_{i=0}^{k} h(i) / N, where N = total pixel count.
  3. Map each intensity via T(k) = round((L-1) · cdf(k)).
T(k) = (L-1) · Σ_{i=0}^{k} h(i) / N

This spreads out the most frequent intensity values, using the CDF's property that mapping through it approximately equalizes the output histogram (exactly, in the continuous case).

std::vector<unsigned char> histogramEqualize(const Image& src) {
    int N = src.rows * src.cols;
    std::vector<int> hist(256, 0);
    for (unsigned char p : src.data) hist[p]++;

    std::vector<unsigned char> lut(256);
    long cum = 0;
    for (int k = 0; k < 256; k++) {
        cum += hist[k];
        lut[k] = (unsigned char) std::round(255.0 * cum / N);
    }
    return lut;   // apply: dst[i] = lut[src.data[i]]
}
Landscape analogy: A hazy photo of a coastline at dawn often has most pixel intensities crammed into a narrow mid-gray band (low contrast, like fog). Histogram equalization "redistributes" that cramped band across the full 0–255 range — dark rocks become darker, bright sky becomes brighter — revealing detail that was hiding in the low-contrast fog.

MEDIUM

Using the 4×4 image above (h(0)=8, h(1)=0, h(2)=0, h(3)=8, N=16, L=4), compute the histogram-equalized mapping T(k) for k=0 and k=3.

Reveal answer
cdf(0) = 8/16 = 0.5 → T(0) = round(3 × 0.5) = round(1.5) = 2. cdf(3) = 16/16 = 1.0 → T(3) = round(3 × 1.0) = 3. So original 0 → 2, and 3 stays 3: the equalized image now has values {2,3} instead of {0,3} — contrast changed, not necessarily "improved" for this degenerate bimodal case, illustrating that equalization is a statistical, not perceptual, criterion.
MEDIUM

Contrast stretching (min-max normalization) and histogram equalization are both point operations addressing "low contrast." What key difference distinguishes them in terms of the transformation function T?

Reveal answer
Contrast stretching applies a single global linear (affine) function T(k) = (k - min)/(max - min) × (L-1) — the same slope everywhere. Histogram equalization applies a nonlinear, data-dependent function derived from the CDF, so it stretches more where the histogram is dense (redistributing based on frequency) and compresses where it's sparse.
HARD

Explain, algorithmically, how you would implement adaptive (local) histogram equalization / CLAHE for a photo of a shadowed rocky coastline with both a dark cave interior and a bright sunlit cliff, and why global equalization fails here. Include the role of tile-based processing and bilinear blending between tiles.

Reveal answer
Global equalization computes one histogram/CDF for the whole image; it cannot simultaneously boost contrast in the dark cave region and the bright cliff region because a single monotonic mapping applies everywhere — enhancing shadow detail would clip/saturate the bright region and vice versa. CLAHE approach: (1) Partition the image into a grid of tiles (e.g., 8×8). (2) Compute a local histogram per tile, clip it at a threshold to limit noise amplification (redistribute clipped counts uniformly), then compute the local CDF-based mapping for that tile. (3) For each pixel, don't apply its own tile's mapping directly — instead, bilinearly interpolate the mapped value using the 4 nearest tile-center mappings, so transitions between tiles are smooth rather than blocky. Complexity: O(rows·cols) for histogram computation, plus O(rows·cols) for the interpolation pass — still linear in image size, with a constant factor from the number of tiles.

4Spatial Filtering & Convolution

Core idea

Unlike point operations, spatial filtering computes each output pixel from a neighborhood of input pixels via a weighted sum — the kernel (mask). This is convolution (or correlation, if the kernel isn't flipped).

g(x,y) = Σ_i Σ_j f(x-i, y-j) · k(i,j)

Key kernels

KernelEffectMechanics
Box / mean filterBlur, noise reductionUniform averaging over a window
GaussianSmooth blur, less "ringing" than boxWeights ∝ exp(-(x²+y²)/2σ²), separable
Sharpening (unsharp mask)Edge enhancementoriginal + α·(original − blurred)
Sobel / PrewittGradient / edge detectionApproximates ∂f/∂x, ∂f/∂y via finite differences
LaplacianSecond-derivative edge/zero-crossing detectionSum of second partial derivatives

Naive convolution in C++ (O(rows·cols·k²) for a k×k kernel)

Image convolve(const Image& src, const std::vector<std::vector<float>>& kernel) {
    int kh = kernel.size(), kw = kernel[0].size();
    int cy = kh/2, cx = kw/2;
    Image out(src.rows, src.cols);
    for (int y = 0; y < src.rows; y++)
      for (int x = 0; x < src.cols; x++) {
        float sum = 0.f;
        for (int j = 0; j < kh; j++)
          for (int i = 0; i < kw; i++) {
            int sy = clamp(y + (j-cy), 0, src.rows-1);  // border handling
            int sx = clamp(x + (i-cx), 0, src.cols-1);
            sum += src.at(sy, sx) * kernel[j][i];
          }
        out.at(y,x) = clampByte(sum);
      }
    return out;
}

Separability speedup

If a 2D kernel K can be written as an outer product K = v · hᵀ of two 1D vectors (true for Gaussian, box filters), convolution reduces from O(k²) work per pixel to O(2k): first convolve every row with h, then every column of the result with v.

Landscape analogy: Think of a Gaussian blur on a photo of a misty coastline as literally simulating fog diffusion — each pixel "borrows" a weighted average of light from its neighbors, with closer neighbors contributing more, exactly like how mist scatters light locally. A Sobel filter, in contrast, acts like a flashlight sweeping across the rocky silhouette, lighting up only where brightness changes sharply — i.e., the boundary between rock and sky.

What is the difference between convolution and correlation in image filtering?

Reveal answer
Convolution flips the kernel both horizontally and vertically (180° rotation) before sliding it over the image; correlation slides the kernel as-is without flipping. For symmetric kernels (e.g., Gaussian, box filter) the two are identical; for asymmetric kernels (e.g., Sobel) they differ.
EASY

Apply a 3×3 mean filter to the center pixel of this 3×3 neighborhood: [10,10,10 / 10,90,10 / 10,10,10]. What's the output?

Reveal answer
Sum = 8×10 + 90 = 170. Average = 170/9 ≈ 18.9 → rounds to 19. The bright outlier (90) is heavily smoothed toward the surrounding value.
MEDIUM

Why does a Gaussian filter blur an image with less "ringing" (halo artifacts) than an ideal box filter of the same size, even though both are low-pass filters?

Reveal answer
In the frequency domain, a box filter's spectrum is a sinc function with significant side-lobes (negative and oscillating), which introduces ringing near sharp edges. A Gaussian's Fourier transform is itself a Gaussian — smooth, positive, and monotonically decaying with no side-lobes — so it attenuates high frequencies gradually without oscillation, avoiding ringing.
MEDIUM

You need to detect horizontal edges (e.g., the waterline where sea meets a rocky cliff) using Sobel. Which Sobel kernel orientation (Gx or Gy) do you use, and why?

Reveal answer
Gy (the kernel that approximates ∂f/∂y, the vertical gradient) — a horizontal edge corresponds to a rapid intensity change as you move vertically (top-to-bottom) across the waterline, so the vertical derivative Gy will have a large magnitude there, while Gx (horizontal gradient) stays near zero along the edge.
HARD

Derive/explain why 2D convolution with an N×N image and a k×k kernel is O(N²k²) naively, then explain two distinct algorithmic strategies to reduce this: (a) kernel separability, (b) FFT-based convolution. State when each is preferable.

Reveal answer
Naive cost: for each of N² output pixels, we sum k² kernel-weighted terms → O(N²k²). (a) Separable convolution: if K = v·hᵀ, convolve rows with h (O(N²k)) then columns of the result with v (O(N²k)), total O(N²k) — a factor-of-k speedup. Preferable when the kernel is genuinely separable (Gaussian, box, Sobel) and k is moderate. (b) FFT-based convolution: by the convolution theorem, spatial convolution equals element-wise multiplication in the frequency domain. Compute FFT(image) and FFT(kernel, zero-padded to image size) in O(N² log N) each, multiply element-wise in O(N²), then inverse FFT in O(N² log N). Total O(N² log N), independent of k. Preferable when k is large (comparable to N) or non-separable, since N²k² can exceed N² log N once k > log N.

5Detecting Edges & Corners

Core idea

Edges are locations of rapid intensity change — modeled via the image gradient ∇f = (∂f/∂x, ∂f/∂y). Corners are points where the gradient changes direction sharply in two independent directions (high "cornerness").

Canny edge detection pipeline

  1. Smoothing: Gaussian blur to reduce noise sensitivity of derivatives.
  2. Gradient computation: Sobel Gx, Gy → magnitude M = √(Gx²+Gy²), direction θ = atan2(Gy,Gx).
  3. Non-maximum suppression: along the gradient direction θ, keep a pixel only if its magnitude M is a local maximum compared to its two neighbors in that direction — thins wide edge ridges to 1-pixel width.
  4. Hysteresis thresholding: two thresholds (high, low). Pixels above high are "strong" edges (kept). Pixels between low and high are kept only if connected (via 8-connectivity, typically BFS/DFS) to a strong edge; otherwise discarded.
M(x,y) = √(Gx(x,y)² + Gy(x,y)²), θ(x,y) = atan2(Gy, Gx)

Harris corner detection — mechanics

For a window W around pixel (x,y), define the structure tensor (second-moment matrix):

M = Σ_{W} [ Ix² IxIy ; IxIy Iy² ] (windowed, often Gaussian-weighted)

Corner response: R = det(M) - k·trace(M)², with k ≈ 0.04–0.06. Large R (both eigenvalues of M large) ⟹ corner; one large eigenvalue ⟹ edge; both small ⟹ flat region.

// Pseudocode: Harris response map
for each pixel (x,y):
    compute Ix, Iy via Sobel
    M[0][0] = gaussianWeightedSum(Ix*Ix, window)
    M[1][1] = gaussianWeightedSum(Iy*Iy, window)
    M[0][1] = M[1][0] = gaussianWeightedSum(Ix*Iy, window)
    float detM  = M[0][0]*M[1][1] - M[0][1]*M[1][0];
    float traceM= M[0][0] + M[1][1];
    R(x,y) = detM - k * traceM * traceM;
// then non-max suppression + threshold on R to get discrete corners
Landscape analogy: Along a rocky coastline, the boundary between the sea and cliffs is an edge — a 1D ridge of rapid brightness change, well captured by gradient magnitude. Where a jagged rock outcrop juts out and the boundary changes direction abruptly (a "point" of the rock), that's a corner — intensity changes sharply in two directions at once, which is exactly what the Harris matrix's two large eigenvalues detect.

In Harris corner detection, what does it mean if both eigenvalues of M are small?

MEDIUM

Why does Canny use two thresholds (hysteresis) instead of a single threshold on gradient magnitude?

Reveal answer
A single threshold forces a hard tradeoff: too high misses faint but genuine edge segments (broken edges), too low lets noise through as spurious edges. Hysteresis lets weak-but-genuine edge pixels survive if they're connected to a strong edge (likely part of the same real contour), while isolated weak responses (likely noise) are discarded — combining sensitivity with robustness.
MEDIUM

Trace non-maximum suppression conceptually: at a pixel on a wide, blurred edge, gradient magnitude is high across 4 pixels in a row (all similar values) perpendicular to the edge direction. What does NMS produce?

Reveal answer
NMS keeps only the single pixel (or few, in case of true ties) that is the local maximum along the gradient direction, suppressing (zeroing) the other 3 — producing a thinned, ideally 1-pixel-wide edge instead of a 4-pixel-wide blurry ridge.
HARD

Explain why the Harris corner response R = det(M) - k·trace(M)² is designed this way instead of just thresholding the smaller eigenvalue λ_min directly (as in the related Shi-Tomasi detector), and give one practical advantage of each formulation.

Reveal answer
det(M) = λ1·λ2 and trace(M) = λ1+λ2, so R is a smooth polynomial combination of both eigenvalues that avoids explicitly computing eigenvalues (which requires a square root / solving a quadratic characteristic equation per pixel) — det and trace are computed directly and cheaply from the matrix entries (Ix², Iy², IxIy sums), making Harris's R computation O(1) per pixel with just arithmetic. Shi-Tomasi directly uses λ_min = min(λ1,λ2) (via the quadratic formula), which is a more direct/interpretable "cornerness" measure (both directions must have significant gradient variation) and tends to produce more stable corners for tracking, at the modest extra cost of computing the eigenvalues explicitly. Practical advantage of Harris: cheaper per-pixel computation (no sqrt), good for real-time. Practical advantage of Shi-Tomasi: more geometrically interpretable, often preferred for feature tracking (e.g., optical flow) since λ_min directly bounds how well a point can be localized in both directions.

6Segmentation

Core idea

Segmentation partitions an image into regions that share some property (intensity, texture, semantic label) — e.g., separating "lung," "kidney," "heart" in a CT scan, or "sky," "sea," "rock" in a coastline photo.

Classical approaches

MethodMechanics
Thresholding (global/Otsu)Pick intensity threshold T; Otsu's method picks T that minimizes intra-class variance (or maximizes inter-class variance) of the two resulting pixel groups, searched over all possible T using cumulative histogram statistics.
Region growingStart from seed pixel(s); iteratively add neighboring pixels (BFS/DFS from a queue) if they satisfy a similarity criterion (e.g., |intensity - region mean| < ε).
WatershedTreat the (gradient) image as a topographic surface; "flood" from local minima; regions merge where water from different basins would meet, forming watershed lines = segment boundaries.
Graph-cut / Normalized cutModel image as a graph (pixels = nodes, edge weight = similarity); segmentation = finding a min-cut (or normalized cut) that separates dissimilar regions while keeping similar pixels together.

Otsu's threshold — algorithmic sketch

int otsuThreshold(const std::vector<int>& hist, int N) {
    double sumAll = 0;
    for (int k = 0; k < 256; k++) sumAll += k * hist[k];

    double sumB = 0; int wB = 0;
    double bestVar = -1; int bestT = 0;

    for (int t = 0; t < 256; t++) {
        wB += hist[t];                     // weight of background class
        if (wB == 0) continue;
        int wF = N - wB;                    // weight of foreground class
        if (wF == 0) break;
        sumB += t * hist[t];
        double mB = sumB / wB, mF = (sumAll - sumB) / wF;
        double between = (double)wB * wF * (mB - mF) * (mB - mF);
        if (between > bestVar) { bestVar = between; bestT = t; }
    }
    return bestT;
}
Landscape analogy: Thresholding a coastline photo into "sea" vs. "rock" works well only if their intensity histograms form two clean bumps (bimodal). Region growing instead starts from a seed click inside the sea and "spreads like water" pixel-by-pixel, absorbing neighbors of similar shade — but it will leak across a boundary if the sea and wet rock have nearly identical brightness (weak/ambiguous boundary), which is exactly the failure mode watershed and graph-cut methods try to handle more robustly.

What is the key assumption that makes global thresholding work well?

In region growing, what data structure is naturally used to manage the "frontier" of pixels to examine next?

MEDIUM

Why does watershed segmentation typically need a "marker" or pre-processing step (e.g., computing the gradient magnitude first, or using distance transform + local minima) instead of running directly on raw pixel intensities?

Reveal answer
Running watershed directly on raw intensities of a noisy/textured image produces severe over-segmentation — every small local minimum becomes its own basin, yielding thousands of tiny regions. Pre-processing (e.g., smoothing, using gradient magnitude so basins correspond to homogeneous regions and ridges correspond to edges, or seeding with markers from another detector) constrains the number of basins to meaningful regions.
MEDIUM

Otsu's method maximizes between-class variance. Explain in one or two sentences why this is mathematically equivalent to minimizing within-class variance for a fixed total variance.

Reveal answer
Total variance of the whole histogram = within-class variance + between-class variance (a fixed decomposition, analogous to ANOVA's total sum of squares). Since total variance is constant regardless of threshold T, maximizing between-class variance over T is exactly equivalent to minimizing within-class variance over T.
HARD

Formulate image segmentation as a graph-cut problem: define the graph, the cost function for a cut, and explain why a plain minimum cut is biased toward tiny/trivial partitions, motivating the Normalized Cut objective.

Reveal answer
Graph construction: each pixel is a node; edges connect nearby pixels (or all pairs, weighted by decaying similarity) with weight w(i,j) reflecting similarity (e.g., based on intensity difference and spatial proximity, often w = exp(-|Ii-Ij|²/σ²) · exp(-dist(i,j)²/σd²)). Min-cut cost: cut(A,B) = Σ_{i∈A, j∈B} w(i,j) — the total edge weight severed to separate the graph into disjoint sets A and B. Problem with plain min-cut: since cut cost only sums severed edge weights without normalizing by partition size, the global minimum is often achieved by isolating a single low-degree node (e.g., one noisy/isolated pixel) as its own tiny partition — because cutting off one node severs very few edges, giving a trivially small cut cost, regardless of whether that's a meaningful segmentation. Normalized Cut fix: Ncut(A,B) = cut(A,B)/assoc(A,V) + cut(A,B)/assoc(B,V), where assoc(A,V) is the total edge weight from A to the whole graph. Dividing by each partition's total association penalizes cuts that isolate small partitions (since assoc(A,V) would be small, inflating the ratio), favoring balanced, semantically meaningful splits. Finding the exact optimal Ncut is NP-hard, but it can be approximated via a generalized eigenvalue problem on the graph Laplacian (spectral clustering).

7Denoising

Core idea

Denoising estimates the "clean" underlying signal f from a noisy observation g = f + n (additive noise model), exploiting the assumption that noise is high-frequency/random while true signal has spatial structure (smoothness, self-similarity, sparsity in some transform domain).

Method comparison

Mean/GaussianLocal weighted averagePoor — blurs edges

Bilateral filter formula

g(x) = (1/W) Σ_{y∈N(x)} f(y) · exp(-‖x-y‖²/2σs²) · exp(-|f(x)-f(y)|²/2σr²)

where W normalizes the weights to sum to 1. The spatial Gaussian term (σs) behaves like a normal blur; the range/intensity Gaussian term (σr) down-weights neighbors whose intensity differs a lot from the center pixel — so it avoids averaging across an edge.

// Pseudocode: bilateral filter at one pixel
float bilateralAt(const Image& src, int x, int y, int radius, float sigmaS, float sigmaR) {
    float centerVal = src.at(y,x);
    float sum = 0, wsum = 0;
    for (int dy = -radius; dy <= radius; dy++)
      for (int dx = -radius; dx <= radius; dx++) {
        int ny = y+dy, nx = x+dx;
        if (!inBounds(ny,nx)) continue;
        float spatialW = exp(-(dx*dx+dy*dy) / (2*sigmaS*sigmaS));
        float diff = src.at(ny,nx) - centerVal;
        float rangeW   = exp(-(diff*diff) / (2*sigmaR*sigmaR));
        float w = spatialW * rangeW;
        sum += w * src.at(ny,nx);
        wsum += w;
      }
    return sum / wsum;
}
Landscape analogy: A noisy nighttime photo of a coastal fort looks grainy — a Gaussian blur would smooth the grain but also blur the sharp stone-vs-sky boundary into a soft gradient. A bilateral filter instead only averages pixels that are both nearby AND similar in brightness — so it smooths the grainy noise within the uniform "sky" region and within the uniform "stone" region separately, while refusing to blend across the sharp boundary between them.

Which filter is generally best for removing "salt-and-pepper" (impulse) noise, and why not a mean filter?

Reveal answer
Median filter — it's robust to outliers since the median of a neighborhood ignores extreme impulse values entirely (an impulse just becomes one candidate that gets ranked to an extreme and discarded from the middle position). A mean filter instead averages the impulse's extreme value into the result, spreading its influence (smearing) rather than removing it.

Sorted: 4,4,5,5,5,6,6,7,200. Median (5th of 9) = 5. The 200 outlier is completely discarded.
MEDIUM

In the bilateral filter, what happens to its behavior as σr → ∞ (range sigma becomes very large)?

Reveal answer
The range weight term exp(-diff²/2σr²) → 1 for all diff (since diff²/σr² → 0), so the range weighting vanishes and the filter reduces to a pure spatial Gaussian blur — it loses its edge-preserving property.
MEDIUM

Why is Non-Local Means often more effective than bilateral filtering on images with repetitive texture, e.g., a photo of a pebble beach?

Reveal answer
Bilateral filtering only considers a local spatial neighborhood around each pixel. Non-Local Means instead compares small patches around the target pixel to patches anywhere else in the image (or a large search window), weighting by patch similarity — so for repetitive texture like pebbles, it can average many genuinely similar patches from distant parts of the image, producing a much better noise estimate than any local neighborhood alone could provide.
HARD

Formulate denoising as a variational/energy-minimization problem (Total Variation denoising): write the objective, explain the role of each term, and describe qualitatively why TV denoising preserves edges better than a quadratic (Tikhonov/L2) smoothness penalty.

Reveal answer
Objective (Rudin-Osher-Fatemi / TV denoising): E(u) = ∫ (u - g)² dx + λ ∫ |∇u| dx First term: data fidelity — keeps the denoised result u close to the noisy observation g. Second term: regularization — penalizes the total variation (L1 norm of the gradient magnitude) of u, encouraging piecewise-smooth solutions. λ balances fidelity vs. smoothness. Why TV (L1 on gradient) preserves edges better than Tikhonov (L2 on gradient, ∫|∇u|² dx): the L2 penalty grows quadratically with gradient magnitude, so it heavily penalizes any large jump (edge) and strongly "wants" to smooth it away — sharp edges get rounded off. The L1 penalty grows only linearly with gradient magnitude, so it doesn't disproportionately punish a single large jump versus many small jumps with the same total variation — the optimizer is willing to keep one sharp edge (low marginal cost per unit of variation) rather than being forced to distribute that variation as blur across many pixels. This is the same sparsity-inducing property of L1 norms seen elsewhere (e.g., LASSO regression) — it favors solutions with few, large, well-localized discontinuities over many small ones.

8Fourier Analysis

Core idea

Any image can be represented as a weighted sum of 2D sinusoids of varying spatial frequency, orientation, and phase — the 2D Discrete Fourier Transform (DFT). Low frequencies capture smooth/slowly-varying content (overall shape, illumination); high frequencies capture fine detail, texture, and edges.

F(u,v) = Σ_{x=0}^{M-1} Σ_{y=0}^{N-1} f(x,y) · e^{-j2π(ux/M + vy/N)}

Key properties (algorithmically relevant)

  • Convolution theorem: convolution in spatial domain = element-wise multiplication in frequency domain, and vice versa. This is the basis of FFT-based fast convolution.
  • Separability: the 2D DFT can be computed as 1D DFT on rows, then 1D DFT on columns — O(N² log N) via FFT instead of O(N⁴) naive.
  • Nyquist–Shannon sampling theorem: to avoid aliasing, sampling rate must exceed 2× the highest spatial frequency present in the signal — directly explains the moiré artifacts discussed in Section 1/2.
  • Low-pass filtering: zero out (or attenuate) high-frequency coefficients, then inverse-FFT → blurred image. High-pass filtering: zero out low frequencies → edge/detail map.

FFT-based low-pass filter — pseudocode

Image lowPassFFT(const Image& src, float cutoffRadius) {
    ComplexImage F = fft2D(src);                 // O(N^2 log N)
    F = fftshift(F);                              // move DC (0 freq) to center
    for (int u = 0; u < F.rows; u++)
      for (int v = 0; v < F.cols; v++) {
        float dist = distFromCenter(u, v, F.rows, F.cols);
        if (dist > cutoffRadius) F.at(u,v) = 0;        // ideal LPF; Gaussian LPF multiplies by a smooth mask instead
      }
    F = ifftshift(F);
    return real(ifft2D(F));                       // back to spatial domain
}
Landscape analogy: Picture the Fourier transform of a coastline photo as decomposing the scene into "waves" of brightness at every scale — the slow, broad wave capturing the overall sea/sky split (low frequency), and the tightly-packed ripples capturing individual rocks and foam texture (high frequency). Zeroing out the high-frequency components and inverting is exactly like photographing the same coastline through fog — the general shapes remain, but all the fine texture (foam, pebbles) disappears.

MEDIUM

State the Nyquist sampling theorem and connect it to why photographing a fine, regularly-spaced iron railing (or brick pattern) on a historical building can produce moiré artifacts in a digital photo.

Reveal answer
Nyquist theorem: to reconstruct a signal without aliasing, the sampling rate must be at least twice the highest frequency component present in the signal. A fine railing/brick pattern has a high spatial frequency (short repeat period); if the camera sensor's pixel pitch samples at a rate below twice that pattern's frequency (once projected through the lens), the true high frequency gets aliased down to a spurious lower frequency in the captured image — appearing as wavy moiré fringes not present in the real scene.
MEDIUM

Why is FFT-based convolution (O(N² log N)) not always faster in practice than direct spatial convolution (O(N²k²)) for small kernels like a 3×3 Sobel?

Reveal answer
For small k (e.g., k=3, k²=9), direct convolution's O(N²k²) = O(9N²) can be smaller than FFT's O(N² log N) once log N exceeds k² — plus FFT has additional overhead (forward FFT of image, forward FFT/padding of kernel, complex multiplication, inverse FFT, and memory for complex-valued intermediate arrays). FFT convolution only wins decisively when the kernel is large (k² approaching or exceeding log N), e.g., large-radius blurs or matched filtering.
HARD

Prove/explain the convolution theorem's practical implication: given a K×K kernel and an image you want to convolve using FFT, describe the correct zero-padding procedure needed to avoid circular

Reveal answer
The DFT inherently treats the signal as periodic (circular) — multiplying two DFTs and inverse-transforming computes circular convolution, where the kernel "wraps around" the image boundary as if the image tiled infinitely. For a K×K kernel applied near the edge of an N×N image, part of the kernel's support would, under circular convolution, incorrectly pull in pixels from the opposite edge of the image (wraparound), producing seam artifacts at the borders that don't correspond to true linear convolution. Correct procedure ("linear convolution via FFT"): zero-pad both the image and the kernel to size at least (N+K-1) × (N+K-1) before taking their FFTs. This creates enough "buffer" so that the circular wraparound region only touches zero-padding rather than real image content, making the result of the (now larger) circular convolution identical to true linear convolution within the valid region. After inverse FFT, crop back to the desired output size (either "full," "same," or "valid," matching standard convolution semantics).

9Principal Component Analysis

Core idea

PCA finds an orthogonal basis (eigenvectors of the data covariance matrix) that captures the directions of maximum variance in the data — used for dimensionality reduction, image compression, denoising (project onto top-k components), and feature extraction (e.g., Eigenfaces).

Algorithm

  1. Flatten each image (or patch) into a vector xᵢ ∈ ℝᵈ. Stack N samples into matrix X ∈ ℝ^{N×d}.
  2. Compute mean vector μ = (1/N)Σxᵢ; center the data: X̃ = X - μ.
  3. Compute covariance matrix C = (1/N) X̃ᵀ X̃ ∈ ℝ^{d×d}.
  4. Eigendecompose C: eigenvectors v_j (principal components / "eigenimages"), eigenvalues λ_j (variance explained along each direction).
  5. Sort eigenvectors by descending eigenvalue; keep top-k as the projection matrix V_k ∈ ℝ^{d×k}.
  6. Project any sample: z = V_kᵀ(x - μ) ∈ ℝᵏ (compressed/reduced representation). Reconstruct: x̂ = μ + V_k z.
C v_j = λ_j v_j (eigenvalue problem on the covariance matrix)

Why it matters for images: the dimensionality trap

For a dataset of N face images each of size 100×100 = 10,000 pixels (d=10,000), the covariance matrix C is 10,000×10,000 — too large to eigendecompose directly if N ≪ d. Trick: eigendecompose the smaller N×N matrix X̃X̃ᵀ instead (its nonzero eigenvalues match those of X̃ᵀX̃), then map the resulting eigenvectors back to d-dimensional space via v_j = X̃ᵀ u_j / √λ_j.

// Conceptual PCA via SVD (numerically preferred over explicit covariance eigendecomposition)
Matrix Xc = X.rowwiseSubtract(mean(X));   // center
// SVD: Xc = U * S * V^T
auto [U, S, V] = svd(Xc);
// columns of V are principal directions; S contains sqrt(eigenvalues) of covariance
Matrix Vk = V.leftCols(k);                // top-k components
Matrix Z  = Xc * Vk;                      // N x k reduced representation
Landscape analogy: Imagine you have 500 photographs of the same rocky coastline taken at different times of day and tide levels. PCA finds the "modes of variation" across the dataset — perhaps the top principal component captures overall brightness (day vs. night), the second captures tide height (how much rock is exposed vs. submerged), and so on. Instead of storing each full-resolution photo, you can store just a handful of coefficients (how much of each mode is present) plus the shared "basis photos" (eigenimages) — a massive compression, as long as most of the coastline's visual variation really does live in a few dominant directions.

MEDIUM

Explain the "SVD trick" for PCA when N (samples) ≪ d (pixels per image): why do we eigendecompose X̃X̃ᵀ (size N×N) instead of X̃ᵀX̃ (size d×d), and how do we recover the d-dimensional eigenvectors afterward?

Reveal answer
X̃X̃ᵀ (N×N) is dramatically cheaper to eigendecompose than X̃ᵀX̃ (d×d) when N≪d — e.g., N=200, d=10,000 makes a 200×200 eigendecomposition trivial versus an infeasible 10,000×10,000 one. The nonzero eigenvalues of X̃X̃ᵀ and X̃ᵀX̃ are identical (they share the same nonzero spectrum, a standard linear algebra fact). Given eigenvector u_j of X̃X̃ᵀ with eigenvalue λ_j, the corresponding d-dimensional eigenvector of X̃ᵀX̃ is recovered as v_j = X̃ᵀu_j / √λ_j (this follows directly from substituting into the eigenvalue equations and normalizing).
HARD

Compare PCA-based image reconstruction to JPEG-style block-DCT compression conceptually: both project data onto a fixed/learned orthogonal basis and keep top coefficients. What is the fundamental difference in how the basis is obtained, and what's the tradeoff (data-dependence vs. generality)?

Reveal answer
DCT (used in JPEG) uses a fixed, universal basis of cosine functions at various frequencies — the same basis regardless of the specific image content. It doesn't require any training data; the same transform applies to any image, block-wise, making it fast, standardized, and hardware-friendly (real-time encode/decode, no need to ship a learned basis). PCA learns a data-dependent basis: the eigenvectors are computed from the specific covariance structure of a given training set (e.g., a collection of face images or coastline photos). This basis is provably optimal in the least-squares reconstruction sense for that specific data distribution (Eckart-Young theorem: truncating to top-k PCA components minimizes reconstruction error among all rank-k linear approximations) — it can achieve far better compression than DCT for data with strong shared structure (e.g., faces, where a handful of "eigenfaces" reconstruct most identity variation). Tradeoff: PCA's optimality is specific to the training distribution — it generalizes poorly to images unlike the training set (e.g., eigenfaces reconstruct faces well but poorly reconstruct arbitrary natural scenes), and both the basis vectors themselves and the projection coefficients must be computed/stored, adding training cost and storage overhead absent in DCT. DCT sacrifices data-optimality for universality, simplicity, and speed.

10Deep Neural Networks for Images

Core idea

Rather than hand-designing features (edges via Sobel, corners via Harris, textures via fixed filter banks), deep networks — especially Convolutional Neural Networks (CNNs) — learn hierarchical feature extractors directly from data, optimized end-to-end for a task (classification, segmentation, detection).

Convolutional layer — mechanics

A conv layer applies a set of learnable K×K filters (analogous to the hand-crafted kernels in Section 4, but their weights are learned via gradient descent) via sliding-window convolution/correlation, producing a stack of feature maps. Stacking layers builds a hierarchy: early layers learn edge/blob-like filters (interpretable, similar to Sobel/Gabor filters); deeper layers combine these into increasingly complex, task-specific features (parts, then whole objects) — matching the slide's diagram of increasingly complex features from simple strokes to full shapes.

y[i,j,c'] = Σ_{di,dj,c} x[i+di, j+dj, c] · W[di,dj,c,c'] + b[c']

Key architectural building blocks

ComponentPurpose
Convolution + activation (ReLU)Learn local, spatially-shared feature detectors; nonlinearity enables complex function approximation
Pooling (max/average)Downsample feature maps, add translation invariance, reduce computation
Batch normalizationStabilize/accelerate training by normalizing layer activations
Skip/residual connectionsEase optimization of very deep networks by allowing gradients to flow directly (ResNet)

Supervised vs. unsupervised feature learning (per the slide's diagram)

The supervised path uses labeled data (e.g., "penguin," "elephant," "kangaroo") to directly optimize features for classification accuracy via backpropagation. The unsupervised path learns features (e.g., via autoencoders) purely from the structure of unlabeled image data, without needing labels — useful when labeled data is scarce.

Advantages and limitations (as flagged in the slides)

  • Advantages: learned features often outperform hand-crafted ones (Sobel, Harris, fixed texture filters) on complex tasks; end-to-end optimization; strong performance with sufficient labeled data.
  • Limitations: requires large labeled datasets; computationally expensive to train; less interpretable ("black box") than classical algorithmic pipelines covered in Sections 3–9; can fail unpredictably on out-of-distribution inputs (e.g., a coastline photo under lighting conditions never seen in training).
Landscape analogy: A classical pipeline for classifying "coastline vs. mountain vs. desert" photos might hand-engineer features: edge density (Sobel), color histograms, texture statistics. A CNN instead learns its own filters directly from thousands of labeled examples — its early layers might independently discover edge-detector-like filters (much like Sobel) purely from data, then combine them in deeper layers into detectors for "wave texture" or "cliff silhouette" without anyone explicitly programming those concepts.

What is the main structural similarity between a classical convolution kernel (e.g., Sobel) and a CNN's convolutional filter?

Both slide a small weighted kernel across the image computing local weighted sums (convolution/correlation) — the mathematical operation is identical. The difference is that Sobel's weights are hand-designed/fixed, while a CNN filter's weights are learned from data via backpropagation.

Name one advantage and one limitation of deep-learning-based image processing versus classical algorithmic methods.

Reveal answer
Advantage: can learn features better suited to complex tasks than any fixed hand-crafted filter, often achieving higher accuracy. Limitation: needs large amounts of labeled training data and compute, and is less interpretable than a classical pipeline with well-understood mathematical steps.
MEDIUM

Why does stacking multiple convolutional layers (rather than using one very large kernel) tend to produce a richer feature hierarchy, per the slide's progression from "strokes → parts → whole shapes"?

Reveal answer
Each layer's output feature map is a function of the previous layer's already-extracted features, not raw pixels — so a filter in layer 2 combining outputs from several layer-1 edge detectors can represent a more complex pattern (e.g., a corner or curve) than any single-layer linear filter could, without needing an enormous kernel. Additionally, stacking small kernels (e.g., two 3×3 layers) achieves a larger effective receptive field with fewer parameters and more nonlinearities (one ReLU per layer) than a single large kernel, increasing representational power for the same or lower parameter cost.
MEDIUM

Relate max-pooling to a concept from Section 5 (edges/corners): why might a max-pooling layer provide some robustness to small translations of a corner-like feature (e.g., the tip of a rocky outcrop) in the input image?

Reveal answer
Max-pooling takes the maximum activation within a local window (e.g., 2×2) and discards the exact position within that window. If a strong "corner detector" filter's peak response shifts by a pixel or two due to a small translation of the actual corner in the image, the max-pooling window is likely to still capture that peak activation somewhere within its receptive field, so the pooled output stays similar — providing local translation invariance, conceptually analogous to how Harris corner detection's non-max suppression already tolerates a "cluster" of high-response pixels near a true corner rather than requiring pixel-exact alignment.
HARD

Contrast a classical segmentation pipeline (e.g., Otsu thresholding or graph-cut, Section 6) with a CNN-based semantic segmentation approach in terms of: (a) what "learning" happens where, (b) how each generalizes to new, unseen coastline images with different lighting/textures, and (c) computational cost tradeoffs at inference time.

Reveal answer
(a) Where learning happens: Classical Otsu/graph-cut has no learned parameters at all — the threshold or graph weights are computed fresh from each individual image's own statistics (its histogram, or per-pixel similarity), so there's no "training" phase; the algorithm's assumptions (bimodality, local similarity) are hand-designed once and applied generically. A CNN-based segmenter (e.g., a U-Net) has millions of learned weights, fit during a training phase on a labeled dataset of many coastline images with ground-truth segment masks; at inference, those fixed learned weights are applied via a single forward pass. (b) Generalization: Otsu/graph-cut adapt automatically to each new image's own statistics (recomputing the threshold/graph per image), so they're somewhat robust to lighting shifts as long as the bimodality/similarity assumption still holds for that image — but they fail hard when that assumption breaks (e.g., overlapping sea/rock intensity distributions in overcast light). A CNN generalizes well to new images similar in distribution to its training data (it has implicitly learned invariances to lighting/texture variation seen during training) but can fail unpredictably on genuinely out-of-distribution inputs (e.g., a coastline photographed in fog if no foggy images were in the training set) since it has no explicit fallback mathematical assumption to rely on. (c) Computational cost: Otsu is extremely cheap at "inference" (O(image size) for histogram + O(256) threshold search); graph-cut is more expensive (max-flow/min-cut algorithms, or eigendecomposition for normalized cut, on a graph with as many nodes as pixels). A CNN's inference cost is dominated by many convolution operations across all layers (can be substantial, though highly parallelizable on GPUs) — but crucially, all of the CNN's "intelligence" was paid for upfront during a (much more expensive) training phase, which the classical per-image methods never require.
