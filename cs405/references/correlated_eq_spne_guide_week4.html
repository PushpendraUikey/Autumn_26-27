1. Core Concepts & Algorithmic Analogies

1.1 Correlated Strategy & Correlated Equilibrium

Correlated strategy. A mapping \(\pi: S_1\times S_2\times\cdots\times S_n \to [0,1]\) with \(\sum_{s\in S}\pi(s)=1\) — a single joint probability distribution over strategy profiles (not a product of independent per-player distributions).
Correlated equilibrium (CE). A correlated strategy \(\pi\) such that for every player \(i\) and every pair \(s_i, s_i' \in S_i\): \[ \sum_{s_{-i}\in S_{-i}} \pi(s_i,s_{-i})\cdot u_i(s_i,s_{-i}) \ \ge\ \sum_{s_{-i}\in S_{-i}} \pi(s_i,s_{-i})\cdot u_i(s_i',s_{-i}) \] i.e., given the recommendation \(s_i\), no deviation to \(s_i'\) is profitable, provided every other player follows their own recommendation. \(\pi\) itself is common knowledge.
CS analogy: Think of the mediator as a distributed-systems arbiterlock manager in a concurrency protocol. A mixed strategy (MSNE) is like each thread independently rolling its own private random number generator with no shared seed — the threads' random choices are statistically independent. A correlated strategy is like a single shared random seed (or a distributed consensus / two-phase-commit coordinator) that hands each thread a correlated instruction drawn from one joint lottery — e.g., "thread A: acquire lock; thread B: wait." Because it's one shared draw, the recommendations can be perfectly anti-correlated (never collide) in a way that two independent RNGs never could. The traffic light is exactly this: it doesn't tell each driver to "go with probability \(p\)" independently — it draws one global light-state and both drivers observe consistent, coordinated instructions derived from it.

1.2 Why We Need a Mediator

Three motivations from the slides: (1) an alternative explanation of rationality — players might really be following external signals rather than internally randomizing; (2) utility can improve for all players versus the best MSNE; (3) computational tractability — CE is dramatically easier to compute than MSNE.
CS analogy: This is the game-theoretic version of moving from local, uncoordinated optimization (each node in a distributed system greedily optimizing with only local information, akin to gradient descent with no message passing) to a centralized scheduler that has global visibility and can hand out a jointly optimal — or at least jointly consistent — assignment. The scheduler can achieve outcomes (like avoiding a collision deterministically) that no amount of independent local randomization can replicate.

Nash solutions: (Wait, Go), (Go, Wait), and a fully-mixed MSNE. A natural mediator plan is \(\pi(W,G)=\pi(W,W)=\pi(G,W)=\tfrac13\), \(\pi(G,G)=0\) — the light never tells both to go, and gives each car an equal share of the two "someone goes" outcomes plus the "both wait" outcome. 1.4 The Equilibrium Hierarchy

\[ \text{SDSE} \subseteq \text{WDSE} \subseteq \text{PSNE} \subseteq \text{MSNE} \subseteq \text{CE} \] (SDSE = strictly-dominant-strategy equilibrium, WDSE = weakly-dominant-strategy equilibrium.) Each notion relaxes the requirements of the one before it, so the set of games possessing that kind of equilibrium only grows as you move right.
SDSE WDSE PSNE MSNE CE
CS analogy: This is exactly a class hierarchy under inheritance / interface refinement. SDSE is like a final class with the strongest guarantees (a dominant strategy — "this action beats everything, no matter what," analogous to a function whose return value is provably correct regardless of input). WDSE relaxes "beats" to "at least ties." PSNE relaxes further to "no unilateral deviation helps, but only relative to what others are actually doing" (a local-optimum guarantee, like a solution stable under a specific fixed test suite rather than all inputs). MSNE further relaxes by allowing randomized responses (like allowing probabilistic/approximate algorithms where deterministic ones might not terminate with a solution). CE is the widest interface: it only requires stability with respect to a shared, correlated recommendation, permitting all the above as special cases (an independent-product distribution — an MSNE — is itself a valid, if degenerate, correlated strategy). Just as every ArrayList "is-a" List, every MSNE "is-a" CE (formally proved via \(\pi^*(s)=\prod_i \sigma_i^*(s_i)\) — the CE built by literally multiplying together everyone's independent mixed strategies).

1.5 Perfect Information Extensive Form Games (PIEFG)

A PIEFG is a tuple \(\langle N, A, H, X, P, (u_i)_{i\in N}\rangle\):
  • \(N\): players.
  • \(A\): the universe of all possible actions.
  • \(H\): the set of all histories (action sequences) — closed under taking prefixes, starting from \(\emptyset\). \(Z\subseteq H\) is the subset of terminal histories (no legal continuation).
  • \(X: H\setminus Z \to 2^A\): the action-set-selection function — legal actions at a non-terminal history.
  • \(P: H\setminus Z \to N\): the player function — whose turn it is at that history.
  • \(u_i: Z \to \mathbb{R}\): payoff of player \(i\), defined only at terminal histories.
CS analogy: \(H\) is exactly the set of all root-to-node paths in a rooted tree (or, more precisely, in a DAG if you think of it abstractly, though PIEFGs are trees) — closed under prefixes is just "every ancestor of a node is also a valid node." \(Z\) is the set of leaf nodes. \(X(h)\) is the out-edges available at internal node \(h\); \(P(h)\) is metadata tagging which process/thread owns the decision at that node (like a turn-based state machine). Computing anything about the game — its value, its equilibrium — means a tree traversal: exactly the kind of recursive walk you'd write to evaluate an expression tree, minimax a game tree, or run a recursive-descent parser over an abstract syntax tree. A strategy \(s_i \in S_i = \times_{\{h: P(h)=i\}} X(h)\) is a complete contingency plan — precisely a lookup table (or a pure function) mapping every node you might ever own to an action, even nodes that will provably never be visited given your own earlier choices. This is identical to a strategy pattern object in software design, or a fully-specified switch statement covering every case even unreachable ones — dead code that still has to be "compiled in" because the type system (the strategy-space definition) demands totality.

1.6 SPNE vs. Plain PSNE on the NFG Conversion

Observation. Converting a PIEFG to its induced Normal Form Game (every full contingency plan becomes one row/column) and finding a PSNE there can produce non-credible threats: an equilibrium strategy might specify an action at some off-equilibrium-path node that the player would never actually rationally take if that node were really reached.
Subgame: the restriction of \(G\) to the descendants of some history \(h\) — i.e., the "sub-tree" rooted at \(h\), treated as its own game.
Subgame Perfect Nash Equilibrium (SPNE): a strategy profile \(s\) such that its restriction to every subgame \(G'\) of \(G\) is itself a PSNE of \(G'\).
CS analogy: A plain PSNE on the flattened NFG is like unit-testing only the program's single top-level entry point / one end-to-end test case — it checks that the overall input/output behavior along one path is stable, but it says nothing about whether the code inside every unreached if-branch is actually correct, because those branches never execute during that one test. SPNE is the game-theoretic analogue of formal verification of every reachable state, or exhaustively unit-testing every function in isolation, including ones your top-level test never calls: you require that the "function" (strategy) installed at every single subgame — every node, reached or not — is independently optimal as if execution started right there. This is exactly why non-credible threats slip past plain PSNE: a "buggy" or "irrational" branch that's dead code under the main equilibrium path doesn't get caught by an NFG-level PSNE check, the same way a bug in an unreachable branch doesn't fail your top-level integration test but would fail a targeted unit test of that branch. This is precisely why the NFG representation, though formally equivalent in terms of listed strategies, is a poor lens for sequential games: it throws away the tree's structural information about when and in response to what an action is chosen, which is exactly the information backward induction needs.

2. Algorithms, Math & Intuition

2.1 Computing a Correlated Equilibrium — Feasibility LP

The CE conditions \[ \sum_{s_{-i}\in S_{-i}} \pi(s_i,s_{-i})u_i(s_i,s_{-i}) \ge \sum_{s_{-i}\in S_{-i}} \pi(s_i,s_{-i})u_i(s_i',s_{-i}), \quad \forall s_i,s_i'\in S_i,\ \forall i\in N \] are linear in the unknowns \(\pi(s)\). Together with \(\pi(s)\ge0\) and \(\sum_{s\in S}\pi(s)=1\), this is a plain feasibility linear program — no support-guessing required.
Complexity comparison (assuming \(|S_i|=m\ \forall i\), \(n\) players):
  • MSNE: total support profiles to search \(= O(2^{mn})\) — exponential in both \(m\) and \(n\).
  • CE: total inequalities \(= O(n\cdot m^2)\) — polynomial. (There are \(m^n\) variables \(\pi(s)\), but only \(O(nm^2)\) constraints, and any standard LP solver runs in time polynomial in the number of variables and constraints.)
Take logs of \(2^{mn}\) versus \(nm^2\) to see the gap explicitly: the MSNE search space is exponential in the exponent (\(mn\) itself is the exponent of 2), while the CE program's size is polynomial in \(m,n\).
CS analogy: MSNE-finding is like brute-force backtracking search over an exponentially large combinatorial space (think: brute-force SAT solving by enumerating every assignment, or exhaustively trying every subset of a power set). CE-finding is like recognizing the same problem can be phrased as an LP relaxation that a polynomial-time algorithm (interior point / simplex in the worst-tractable cases) can solve directly — the same phenomenon as when a seemingly combinatorial problem (e.g., max-flow, matching) turns out to have an LP formulation solvable in poly-time, versus a naively-combinatorial sibling problem that's NP-hard. The mediator doesn't just change the economics of the game; it changes the computational complexity class of finding a stable outcome — from an exponential support-enumeration problem to a polynomial-size LP.

2.2 Backward Induction — Reading It As Recursive DFS / DP

Algorithm (Backward Induction). 
function BACK_IND(history h):
    if h in Z:                          # base case: leaf node
        return u(h), None               # (payoff vector, no action)

    best_util[P(h)] = -infinity
    for a in X(h):                      # try every legal action/child
        util_at_child = BACK_IND(h + a)          # recurse into subtree
        if util_at_child[P(h)] > best_util[P(h)]:
            best_util[P(h)]   = util_at_child[P(h)]
            best_action[P(h)] = a
    return best_util, best_action
CS analogy: This is textbook post-order DFS with memoization — structurally identical to:
  • the minimax algorithm for two-player zero-sum game trees (chess engines, tic-tac-toe solvers) — the only difference is minimax alternates maximize/minimize for a zero-sum game, while BACK_IND generalizes to each player maximizes their own payoff coordinate at their own nodes (a straightforward multi-player generalization);
  • evaluating an expression tree bottom-up — you can't know a node's value until you've recursively resolved all its children, exactly like evaluating (2+3)*4 requires resolving the + subtree before the *;
  • dynamic programming on a tree (e.g., "maximum independent set in a tree" or "diameter of a tree") — the recursion computes and caches an optimal sub-solution at every node exactly once, and the parent combines children's optimal sub-solutions rather than recomputing from scratch. If you memoize on the history string \(h\) (useful when the same sub-position can be reached via multiple paths, e.g., in a DAG-shaped extensive game rather than a pure tree), this becomes literally the same code pattern as memoized recursive DP.
The function's return value best_action[P(h)] at every single node — not just the ones actually visited under the final equilibrium path — is exactly what builds a full SPNE strategy: a totally-defined lookup table, just like 1.5's "strategy = complete contingency plan" idea.

2.3 The Centipede Game — Backward Induction's Famous Paradox

A "centipede" alternates between two players; at each stage the current player can defect (D), ending the game with a modest, unequal split, or continue (A), risking the turn to the other player but growing the eventual pie. Backward induction, applied from the very last node backward, predicts immediate defection at the first move.
Why backward induction forces immediate defection: At the very last decision node, the mover strictly prefers D to A (by construction of the payoffs). Anticipating this, the second-to-last mover also strictly prefers D now rather than handing over a turn that will certainly end in the other player defecting one step later for a worse personal payoff. This unravels all the way back to move 1: the very first player defects immediately, "leaving money on the table" that could have been earned had both players cooperated for a while.
Empirical paradox: Real subjects (except, notably, grandmaster-level strategic players) rarely defect at move 1 — most continue for several rounds. Claimed explanations: altruism/social preferences, bounded computational capacity, and differing beliefs about the opponent's rationality. The deeper critique of SPNE itself: subgame perfection's defining requirement talks about "what's optimal if this history is reached" — but the induction's own logic, applied one level up, may already show that history is never reached under the equilibrium, creating a strange self-referential tension between "optimal conditional on being there" and "provably never there."
CS analogy: This is the game-theoretic sibling of unbounded vs. depth-limited recursion / halting-condition brittleness. A true backward-induction solver is like a program that must fully unwind a deep recursive call stack all the way to the base case before it can decide the very first move — exactly like requiring a full, exact minimax search to the leaves before making move 1 in a huge game tree (computationally infeasible for chess, hence real engines use depth-limited search with heuristic evaluation instead of "true" backward induction). Real human players behave more like iterative deepening or depth-limited game-tree search with a heuristic cutoff — they reason a few plies ahead, not all the way to the terminal leaf, which is exactly why they don't reproduce the fully-unwound recursive prediction. The Centipede paradox is a vivid illustration that an algorithm that is correct in the limit (true backward induction, given unbounded lookahead) can produce wildly different real-world behavior than a resource-bounded approximation of the same algorithm — a very familiar tension to anyone who has swapped an exact algorithm for a heuristic one under a time or memory budget.

3.1 Correlated Strategy & Equilibrium

Q1. Why is a correlated strategy strictly more general than a pair of independent mixed strategies?
A mixed-strategy profile \((\sigma_1,\sigma_2)\) always induces a joint distribution over \(S_1\times S_2\) of the special product form \(\pi(s_1,s_2)=\sigma_1(s_1)\sigma_2(s_2)\) — the two players' realized actions are statistically independent. A correlated strategy \(\pi\) can be any joint distribution over \(S_1\times S_2\), including ones that are not expressible as a product of two marginals (e.g., perfectly anti-correlated distributions like \(\pi(W,G)=\pi(G,W)=\tfrac12\), \(\pi(W,W)=\pi(G,G)=0\)). So every mixed-strategy profile is a special case of a correlated strategy, but not vice versa — exactly why MSNE \(\subseteq\) CE in the hierarchy.
Q2. In the Busy Crossroad game, why can the mediator's plan \(\pi(G,G)=0\) achieve something neither player's individual mixed strategy can replicate alone?
Under any independent mixed strategy pair \((\sigma_1,\sigma_2)\) with both \(\sigma_1(\text{Go})>0\) and \(\sigma_2(\text{Go})>0\), the product-form joint distribution necessarily assigns \(\sigma_1(\text{Go})\cdot\sigma_2(\text{Go})>0\) probability to the catastrophic \((\text{Go},\text{Go})\) outcome — there is no way for two independent random draws to "know about" each other and avoid colliding. A correlated strategy is not constrained to the product form, so the mediator can directly zero out \(\pi(G,G)\) while keeping both marginal "sometimes go" probabilities positive — coordination that independent randomization can never achieve exactly.
Q3. What does it mean for \(\pi\) to be "common knowledge," and why is this necessary for CE to make sense as an equilibrium concept?
Common knowledge means every player knows the distribution \(\pi\) the mediator is using, knows that every other player knows it too, and so on ad infinitum. This matters because the CE incentive constraint is a statement about a player's best response given their belief about what everyone else will do — and that belief is derived directly from \(\pi\) conditioned on the player's own recommendation. If \(\pi\) weren't common knowledge, players couldn't correctly compute the conditional distribution over others' actions implied by their own signal, so "no profitable deviation" would not be a well-defined or verifiable condition — the whole equilibrium concept would be on shaky ground.

3.2 The Equilibrium Hierarchy

Q4. Why is every PSNE also an MSNE — what would go wrong if it weren't?
A PSNE is literally a degenerate mixed strategy profile where each \(\sigma_i^*\) places probability 1 on a single pure action. The MSNE condition \(u_i(\sigma_i^*,\sigma_{-i}^*)\ge u_i(\sigma_i,\sigma_{-i}^*)\ \forall \sigma_i\in\Delta S_i\) reduces, by the "check-only-pure-deviations" theorem from Week 3, to exactly the PSNE condition \(u_i(s_i^*,s_{-i}^*)\ge u_i(s_i,s_{-i}^*)\ \forall s_i\in S_i\). So a PSNE automatically satisfies the (weaker, more general) MSNE definition. If it didn't, the hierarchy would be broken and MSNE would fail to be a genuine generalization of PSNE — which would undermine using MSNE existence (Nash 1951) as a fallback whenever PSNE fails to exist.
Q5. Can a CE ever give strictly higher total welfare than the best MSNE of the same game? Use the Busy Crossroad numbers to argue your answer.
Yes — this is exactly what Problem 3 in the practice set demonstrates. The CE \(\pi(W,G)=\pi(W,W)=\pi(G,W)=\tfrac13\) gives each player expected payoff 1 (total welfare 2) while assigning zero probability to the disastrous \((G,G)\) outcome. The fully-mixed MSNE, by contrast, must put positive independent probability on Go for both players (since it's a genuine mixed equilibrium), which forces a strictly positive \((\tfrac{2}{13})^2\approx2.4\%\) chance of the \(-10,-10\) collision, dragging expected welfare below what the CE achieves. This is a general phenomenon, not a coincidence of this example: because CE's feasible set is a strict superset of the (converted) MSNE outcomes, the best achievable welfare under CE is always weakly higher, and strictly higher whenever an MSNE's independence forces some bad joint outcome that a correlated device can rule out.
Q6. What is the exact difference between the SDSE and WDSE defining inequalities, and why does SDSE \(\subseteq\) WDSE follow?
SDSE requires a strict inequality against every other strategy: \(u_i(s_i^*,s_{-i}) > u_i(s_i,s_{-i})\ \forall s_i\ne s_i^*,\ \forall s_{-i}\). WDSE relaxes this to a non-strict (weak) inequality: \(u_i(s_i^*,s_{-i}) \ge u_i(s_i,s_{-i})\). Every strict inequality is trivially also a weak (non-strict) inequality, so any strategy satisfying the SDSE condition automatically satisfies the WDSE condition — hence SDSE \(\subseteq\) WDSE. The converse fails: a strategy that only weakly dominates (ties on some opponent action) satisfies WDSE but not the strictly-stronger SDSE requirement.

3.3 Perfect Information Extensive Form Games (PIEFG)

Q7. Why must \(H\) be closed under taking prefixes — what would break if it weren't?
Prefix-closure encodes the basic fact that you cannot be at move 5 of a sequential game without having actually passed through moves 1–4 first — every node's entire ancestor chain must itself be a legitimate, reachable game state. If \(H\) allowed some history \(h\) without also containing all of \(h\)'s prefixes, the "tree" would effectively have dangling nodes with no valid path from the root — you could not actually walk to a state whose parent doesn't exist. This mirrors the basic well-formedness requirement for any tree/DAG data structure: every non-root node must have a valid path back to the root, or graph-traversal algorithms like backward induction have no well-defined way to recurse down to it in the first place.
Q8. In the brother-sister chocolate game, why does Sister's strategy space have size \(2^3=8\) even though only one of the three branches is ever actually played?
A strategy is a complete contingency plan — Sister must specify what she would do at every node where she gets to move, not just the one node that ends up being reached once Brother's actual choice is fixed. Since Sister has three distinct decision nodes (one following each of Brother's three possible proposals \(2\text{-}0\), \(1\text{-}1\), \(0\text{-}2\)), and she picks from \(\{A,R\}\) at each, her strategy space is the Cartesian product \(\{A,R\}\times\{A,R\}\times\{A,R\}\), size \(2^3=8\) — even though, once Brother actually proposes (say) \(1\text{-}1\), only her plan for that one node ever gets executed. This is exactly the "strategy pattern object with a fully-specified switch statement, including unreachable cases" idea from §1.5.
Q9. What is the difference between \(X(h)\) and \(P(h)\), and why do we need both?
\(X(h)\) answers "what actions are legally available at history \(h\)?" — it's the out-edge set of node \(h\) in the tree. \(P(h)\) answers a completely orthogonal question: "whose turn is it to choose among those actions?" You need both because knowing the legal moves at a node tells you nothing about who is entitled to make that move, and knowing whose turn it is tells you nothing about what options they have. Together, \((X(h), P(h))\) fully specify the local decision problem at every node — analogous to a state machine transition needing both a set of valid transitions from a state and a tag for which subsystem/thread owns firing that transition.

3.4 SPNE vs. PSNE

Q10. In your own words, why can a PSNE on the induced NFG rely on a non-credible threat, but an SPNE cannot?
A PSNE on the flattened NFG only checks that no player wants to unilaterally deviate given the full strategy profile as a package — and because a full strategy specifies behavior at unreached nodes too, a "bad" (irrational) action buried in an off-path branch is invisible to this check, since changing it doesn't change anyone's realized payoff along the equilibrium path. SPNE explicitly requires the restriction of \(s\) to be a PSNE of every subgame, including the ones that are off the main path — so an irrational action hidden in an unreached branch gets caught the moment you evaluate that specific subgame in isolation, exactly the way a targeted unit test would catch a bug that a single end-to-end integration test misses.
Q11. Is every SPNE a PSNE of the induced NFG? Is the converse true?
Yes, every SPNE is a PSNE of the induced NFG: subgame perfection includes optimality at the whole-game subgame (the root), which is exactly the PSNE condition on the flattened game. The converse is false — as Problem 2 demonstrates directly, the induced NFG has three PSNEs, (AG,CF), (AH,CF), (BH,CE), but only (AG,CF) is subgame perfect. So SPNE is a strict refinement (subset) of PSNE-on-the-NFG, not an equivalent characterization.
Q12. Why might real-world contract design (e.g., "if you break this agreement, I'll never do business with you again") try to deliberately make an otherwise non-credible threat credible?
A threat like "I'll cut you off forever" is often non-credible in a one-shot backward-induction sense, because carrying it out may also hurt the threatener (lost future business, reputational cost of pettiness, etc.) — exactly like Player 1's threat of \(H\) at node γ in Problem 2, which Player 1 would never actually want to carry out. Real institutions try to convert such threats into credible ones by attaching binding, third-party-enforced consequences (legal penalty clauses, escrow, reputational systems, repeated-game structures) so that carrying out the "threat" becomes the threatener's genuine best response if the relevant subgame is ever reached — effectively re-engineering the payoffs at that subgame so backward induction itself validates the threat, rather than relying on the other party simply believing an empty promise.

3.5 Computing Correlated Equilibrium (LP)

Q13. Why does the CE feasibility program have \(O(n\cdot m^2)\) inequalities, and what does each one represent?
Each inequality corresponds to one (player \(i\), suggested action \(s_i\), deviation action \(s_i'\)) triple: "if told to play \(s_i\), don't want to switch to \(s_i'\)." For each of the \(n\) players there are \(m\) possible suggested actions, and for each suggested action there are up to \(m-1\) possible deviations — giving roughly \(n\cdot m\cdot(m-1) = O(n\cdot m^2)\) total constraints. This is polynomial in \(m\) and \(n\) separately (as opposed to the MSNE search space, which is exponential in the product \(mn\)), which is exactly the source of CE's computational tractability advantage.
Q14. Why doesn't adding an objective (e.g., maximize total welfare \(\sum_i u_i\)) change the LP's complexity class?
The CE conditions already define a feasible region that is a convex polytope carved out entirely by linear inequalities and one linear equality (the simplex constraint). Adding a linear objective function on top turns the feasibility problem into a standard linear program (optimize a linear objective over a polytope) rather than just a feasibility check — but this is still squarely inside the same polynomial-time-solvable class (LP is solvable in polynomial time via interior-point methods). Optimizing over a convex polytope costs asymptotically the same order of computation as merely testing feasibility of that same polytope; you haven't introduced any new combinatorial structure, just a direction to search within the already-tractable feasible set.
Q15. Why can't we write MSNE-finding as a single linear program the way we can for CE (for \(n>2\) players, or even for \(n=2\) in general)?
The MSNE indifference conditions involve products of each player's own mixed-strategy probabilities with the others' — e.g., in the support-based feasibility program from Week 3, the expected utility term is \(\sum_{s_{-i}}\big(\prod_{j\ne i}\sigma_j(s_j)\big)u_i(s_i,s_{-i})\), a product of decision variables belonging to different players. That makes the constraints genuinely nonlinear (bilinear/multilinear) in the unknowns whenever \(n\ge2\) players' probabilities multiply together — except in the special two-player zero-sum case, where the maxmin/minmax LP duality from Week 3 rescues linearity. CE sidesteps this entirely because \(\pi\) is a single joint distribution — there's no product of independent per-player variables anywhere in the CE constraints, since \(\pi(s_i,s_{-i})\) is already one variable, not a product of several.

3.6 Backward Induction

Q16. Why must BACK_IND fully resolve all of a node's children before it can return a value for that node — could it work top-down instead?
A node's optimal action and value are defined as "the best among my children's already-resolved values" — you cannot know whether action \(a\) is Player \(P(h)\)'s best choice at \(h\) without first knowing what payoff each child subtree actually delivers, and that in turn depends on the choices made further down the tree. This is inherently a post-order (children-before-parent) computation, exactly like you cannot evaluate \((2+3)*4\) by looking at \(*\) before resolving \(+\). A top-down pass could only propagate partial information (like legal-move sets) downward, but it cannot compute optimal values top-down because those values are only well-defined once the recursion bottoms out at the base case (terminal histories) and works its way back up.
Q17. In what precise sense is BACK_IND a generalization of the minimax algorithm rather than a different algorithm?
Minimax is the special case of BACK_IND restricted to two-player, zero-sum games, where "Player \(P(h)\) maximizes their own payoff coordinate" collapses to "one player maximizes a scalar value \(v\), the other minimizes that same scalar \(v\)" (since \(u_2=-u_1\)). BACK_IND as given in the slides is strictly more general: at each node, whichever player owns that node maximizes their own payoff coordinate from the full payoff vector, without requiring the other player's payoff to be the negative of it — which is exactly what's needed for general-sum, \(n\)-player extensive games (like the Brother-Sister game, which is not zero-sum).
Q18. If a game tree has depth \(d\) and branching factor \(b\) at every node, what is the time complexity of BACK_IND, and why does this matter for real games like chess?
Without memoization across different paths reaching structurally-identical states, BACK_IND visits every node of the tree exactly once, and a full \(b\)-ary tree of depth \(d\) has \(O(b^d)\) nodes — so the algorithm runs in \(O(b^d)\) time. For chess, \(b\approx35\) and a full game can run to \(d\approx80\) or more plies, giving a tree with roughly \(10^{123}\) nodes (the slides cite \(\sim10^{150}\) states) — utterly infeasible to fully traverse. This is exactly why real chess engines abandon exact backward induction in favor of depth-limited search with a heuristic evaluation function at the cutoff depth, trading exactness for tractability — the same tension discussed under the Centipede game.

3.7 Limitations of SPNE & the Centipede Game

Q19. Why does backward induction predict immediate defection in the Centipede game even though mutual cooperation for a while is better for both players?
Backward induction reasons from the last possible move backward: at the very last node, the mover strictly prefers to defect (that's how the payoffs are constructed). Knowing this, the second-to-last mover realizes that continuing only hands control to someone who will defect next turn anyway (for a worse personal outcome than defecting right now), so they defect instead. This reasoning telescopes all the way back to move 1 — each player "reasons through" every future node's already-determined outcome and concludes that continuing is never individually optimal, even though the players are jointly leaving a larger, mutually beneficial pie on the table by not continuing longer.
Q20. What is the specific critique the slides raise against the "defining principle" of SPNE itself, independent of empirical evidence from experiments?
SPNE's definition requires evaluating "what is optimal if history \(h\) is reached," treating every subgame as its own self-contained decision problem to be solved on its own terms. But the very induction that produces the SPNE prediction can simultaneously prove that certain histories (like continuing past move 1 in the Centipede game) are never actually reached under that same equilibrium. This creates a philosophical tension: the equilibrium concept demands rationality conditional on being in a state that the equilibrium itself proves is unreachable — a kind of self-undermining counterfactual that some game theorists argue makes the "credible" backward-induction outcome less obviously "rational" than it first appears.
Q21. The slides mention three candidate explanations for why real subjects don't defect immediately: altruism, limited computational capacity, and incentive differences. Pick one and explain, in game-theoretic terms, how it would formally break the backward-induction argument.
Take limited computational capacity: if a real player can only look ahead a bounded number of plies (say, 2 or 3) rather than fully unwinding the recursion to the terminal leaf, they simply never compute the full chain of "opponent will defect next, so I should defect now" reasoning that requires seeing all the way to the end of a potentially long centipede. Formally, this is equivalent to running BACK_IND with a depth cutoff and a heuristic value function substituted in at that cutoff (exactly as discussed for chess engines in Q18) — and if the heuristic at the cutoff depth doesn't perfectly encode "the true backward-induction value," the resulting "locally optimal" action at move 1 can easily be Continue rather than Defect, breaking the chain the exact algorithm would have produced.

Solution — Problem 1 (Easy)

(a) Player 2's decision at nodes α and β (base-case recursion resolves first):

At node α: l gives Player 2 a payoff of 1; r gives Player 2 a payoff of 4. Since \(4>1\), BACK_IND returns best_action[P2] = r with value \((1,4)\).

At node β: l gives Player 2 a payoff of 2; r gives Player 2 a payoff of 5. Since \(5>2\), BACK_IND returns best_action[P2] = r with value \((0,5)\).

(b) Player 1's decision at the root (using the memoized values just computed as the "effective payoff" of each branch):

\(L\) leads (via P2's optimal r) to \((1,4)\) → Player 1 gets 1.
\(R\) leads (via P2's optimal r) to \((0,5)\) → Player 1 gets 0.

Since \(1 > 0\), BACK_IND returns best_action[P1] = L at the root.

(c) Full SPNE strategy profile:

Player 1: play \(L\) at the root.
Player 2: play \(r\) at node α and \(r\) at node β (a complete contingency plan covering both of Player 2's possible nodes, even though only α is ever actually reached).
Equilibrium path outcome: \((L, r)\) → payoff \((1,4)\).

Node β and its action are "dead code" along the realized path — but a full strategy (and hence a full SPNE) must specify what Player 2 would do there too, exactly as the definition of \(S_i\) in §1.5 requires.

Solution — Problem 2 (Medium)

(a) Strategy spaces:

Player 1's strategy is a pair (action at root, action at node γ) — even though γ is only reached if Player 1 played \(B\) and Player 2 played \(F\): \[ S_1 = \{AG,\ AH,\ BG,\ BH\} \] Player 2's strategy is a pair (action at node α, action at node β): \[ S_2 = \{CE,\ CF,\ DE,\ DF\} \]

(b) The induced \(4\times4\) NFG (Player 1's payoff, Player 2's payoff). Each cell is computed by walking the tree: e.g. row AG vs column CF means root=\(A\), so we go straight to node α, and column CF's first component is \(C\) → outcome \((3,8)\), regardless of the unused \(G\)/\(F\) components.

CECFDEDF
AG3, 83, 88, 38, 3
AH3, 83, 88, 38, 3
BG5, 52, 105, 52, 10
BH5, 51, 05, 51, 0

(c) All PSNEs (checking every cell for unilateral deviations):

• (AG, CF) = (3,8): Player 1's column-CF payoffs are \(3,3,2,1\) for AG,AH,BG,BH — max is 3, tied at AG/AH, so AG is a best response. Player 2's row-AG payoffs are \(8,8,3,3\) for CE,CF,DE,DF — max is 8, tied at CE/CF, so CF is a best response. ✓ PSNE.

• (AH, CF) = (3,8): identical reasoning (AH ties AG for Player 1; CF ties CE for Player 2). ✓ PSNE.

• (BH, CE) = (5,5): Player 1's column-CE payoffs are \(3,3,5,5\) — max is 5, tied at BG/BH, so BH is a best response. Player 2's row-BH payoffs are \(5,0,5,0\) — max is 5, tied at CE/DE, so CE is a best response. ✓ PSNE.

No other cell achieves a simultaneous best response in both directions (you can check e.g. (BG,CF)=(2,10): Player 1 would deviate to AG for 3>2 — not a PSNE).

(d) Subgame perfection check. First solve the subgames directly via backward induction:

Subgame at node γ (Player 1 chooses G vs H): \(G\to(2,10)\) gives Player 1 a payoff of 2; \(H\to(1,0)\) gives Player 1 a payoff of 1. Since \(2>1\), the only PSNE of this one-player subgame is \(G\). So any equilibrium specifying \(H\) at node γ is not subgame perfect — it fails the definition directly, whether or not γ is reached under the overall profile.

Subgame at node β (Player 2 chooses E vs F, given γ resolves to G per the above): \(E\to(5,5)\) gives Player 2 a payoff of 5; \(F\to\)(via γ's optimal G)\(\to(2,10)\) gives Player 2 a payoff of 10. Since \(10>5\), the unique PSNE of this subgame is \(F\).

Subgame at node α (Player 2 chooses C vs D): \(C\to(3,8)\) gives Player2 payoff 8; \(D\to(8,3)\) gives Player2 payoff 3. Unique PSNE: \(C\).

Root subgame (whole game): Player 1 compares \(A\to\)(via α's optimal \(C\))\(\to(3,8)\), payoff 3, versus \(B\to\)(via β's optimal \(F\), which itself routes through γ's optimal \(G\))\(\to(2,10)\), payoff 2. Since \(3>2\), Player 1's unique optimal root action is \(A\).

Unique SPNE: Player 1 plays \((A, G)\) = AG; Player 2 plays \((C, F)\) = CF. Outcome: \((3,8)\).

Now classify each of the three PSNEs from (c):

  • (AG, CF) — exactly matches the backward-induction result. This is the (unique) SPNE — fully credible at every subgame.
  • (AH, CF) — relies on Player 1's off-path commitment to play \(H\) at node γ, but node γ's subgame shows \(G\) strictly dominates \(H\) for Player 1 (\(2>1\)). Since node γ is never reached when Player 1 plays \(A\) at the root, this "threat" of \(H\) is never tested, which is exactly why it survives as an NFG-level PSNE — but it is a non-credible threat and this profile is not subgame perfect.
  • (BH, CE) — here Player 2's choice of \(E\) at node β is rationalized only by assuming Player 1 would actually play the irrational \(H\) at node γ if reached (making \(F\) look bad, payoff 0, versus \(E\)'s payoff 5). But since \(G\) is actually optimal for Player 1 at γ, \(F\) truly leads to payoff 10 for Player 2 — so Player 2 would strictly prefer to deviate to \(F\) if Player 1's threat were credible. This profile is propped up by the same non-credible threat (\(H\)) and is therefore also not subgame perfect.

This is a clean illustration of the slide's core point: the NFG flattening admits 3 PSNEs, but subgame perfection (which requires optimality at every subgame, not just along the realized path) prunes it down to the single credible outcome \((AG,CF)\).

Solution — Problem 3 (Hard)

(a) Deriving the four CE constraints. Recall the general CE condition: for player \(i\), suggested action \(s_i\), deviation \(s_i'\): \[ \sum_{s_{-i}} \pi(s_i,s_{-i})u_i(s_i,s_{-i}) \ge \sum_{s_{-i}} \pi(s_i,s_{-i})u_i(s_i',s_{-i}) \]

Payoffs: \(u_1(W,W){=}0,\ u_1(W,G){=}1,\ u_1(G,W){=}2,\ u_1(G,G){=}{-}10\); \(u_2(W,W){=}0,\ u_2(G,W){=}1,\ u_2(W,G){=}2,\ u_2(G,G){=}{-}10\).

Player 1, suggested \(W\), deviate to \(G\) (weight by \(\pi(W,\cdot)=a,b\)): \[ a\cdot u_1(W,W) + b\cdot u_1(W,G) \ \ge\ a\cdot u_1(G,W) + b\cdot u_1(G,G) \] \[ 0\cdot a + 1\cdot b \ \ge\ 2a + (-10)b \quad\Longrightarrow\quad b \ge 2a - 10b \quad\Longrightarrow\quad \boxed{2a - 11b \le 0} \]

Player 1, suggested \(G\), deviate to \(W\) (weight by \(\pi(G,\cdot)=c,d\)): \[ c\cdot u_1(G,W) + d\cdot u_1(G,G) \ \ge\ c\cdot u_1(W,W) + d\cdot u_1(W,G) \] \[ 2c + (-10)d \ \ge\ 0\cdot c + 1\cdot d \quad\Longrightarrow\quad 2c - 10d \ge d \quad\Longrightarrow\quad \boxed{2c - 11d \ge 0} \]

Player 2, suggested \(W\), deviate to \(G\) (weight by \(\pi(\cdot,W)=a,c\)): \[ a\cdot u_2(W,W) + c\cdot u_2(G,W) \ \ge\ a\cdot u_2(W,G) + c\cdot u_2(G,G) \] \[ 0\cdot a + 1\cdot c \ \ge\ 2a + (-10)c \quad\Longrightarrow\quad c \ge 2a - 10c \quad\Longrightarrow\quad \boxed{2a - 11c \le 0} \]

Player 2, suggested \(G\), deviate to \(W\) (weight by \(\pi(\cdot,G)=b,d\)): \[ b\cdot u_2(W,G) + d\cdot u_2(G,G) \ \ge\ b\cdot u_2(W,W) + d\cdot u_2(G,W) \] \[ 2b + (-10)d \ \ge\ 0\cdot b + 1\cdot d \quad\Longrightarrow\quad 2b - 10d \ge d \quad\Longrightarrow\quad \boxed{2b - 11d \ge 0} \]

Plus the simplex constraints: \[ a+b+c+d = 1, \qquad a,b,c,d \ge 0. \]

Full feasibility LP:

\[ \begin{aligned} 2a - 11b &\le 0 \\ 2c - 11d &\ge 0 \\ 2a - 11c &\le 0 \\ 2b - 11d &\ge 0 \\ a+b+c+d &= 1 \\ a,b,c,d &\ge 0 \end{aligned} \]

(b) Verifying the proposed plan \(a=b=c=\tfrac13,\ d=0\):

  • \(2a-11b = 2(\tfrac13)-11(\tfrac13) = \tfrac{2-11}{3} = -3 \le 0\) ✓
  • \(2c-11d = 2(\tfrac13)-0 = \tfrac23 \ge 0\) ✓
  • \(2a-11c = 2(\tfrac13)-11(\tfrac13) = -3 \le 0\) ✓
  • \(2b-11d = 2(\tfrac13)-0 = \tfrac23 \ge 0\) ✓
  • \(a+b+c+d = \tfrac13+\tfrac13+\tfrac13+0 = 1\) ✓, all four values \(\ge0\) ✓

All six constraints hold — yes, this is a valid correlated equilibrium.

(c) Expected payoffs and comparison to MSNE. Under \(\pi\) with \(a=b=c=\tfrac13,d=0\): \[ \mathbb{E}[u_1] = a\cdot0 + b\cdot1 + c\cdot2 + d\cdot(-10) = \tfrac13(0) + \tfrac13(1) + \tfrac13(2) + 0 = \tfrac33 = 1 \] \[ \mathbb{E}[u_2] = a\cdot0 + b\cdot2 + c\cdot1 + d\cdot(-10) = \tfrac13(0) + \tfrac13(2) + \tfrac13(1) + 0 = \tfrac33 = 1 \]

So this CE gives each player an expected payoff of 1, and — crucially — it does so with zero probability of the catastrophic \((Go,Go)\) collision ever occurring (since \(d=\pi(G,G)=0\)). Compare this to the fully-mixed MSNE of this game: solving the indifference conditions (Player 1 indifferent between W,G against Player 2's mix \((q,1-q)\) on (Wait,Go): \(0\cdot q + 1(1-q) = 2q + (-10)(1-q) \Rightarrow q^*=\tfrac{11}{13}\), and by symmetry Player 2's mix is the same) — under the MSNE, both players independently randomize, so the "both Go" collision \((-10,-10)\) occurs with strictly positive probability \((1-q^*)^2 = (\tfrac{2}{13})^2 = \tfrac{4}{169} \approx 2.4\%\) of the time, dragging the MSNE's expected payoff down. The CE strictly dominates the MSNE here precisely because the shared randomization device can guarantee the two cars' recommendations are never simultaneously "Go" — exactly the coordination a traffic light provides that two independent coin-flips cannot.
